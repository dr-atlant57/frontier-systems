MERP — Multi-Agent Epistemic Reliability Protocol

A controlled benchmark for preserving evidence, provenance and decision authority in collaborating agent systems.

Architecture brief / conceptual design. This describes a proposed system and next steps, not a completed deployment.

ENRU
The architectural problemProposed architectureCritical validation questionsRelevant partners

01 / ROOT

The architectural problem

When agents exchange assertions and modify a shared workspace, epistemic mistakes can become entangled with unauthorized changes. An experiment without a fixed baseline cannot tell whether improvement came from the architecture or a moving test setup.

02 / DESIGN

Proposed architecture

Establish an inspectable experimental contract: known initial conditions, adversarial scenarios, permitted changes, measurement points and frozen evaluation rules.

System components

Provenance graph

Trace each consequential assertion back to sources, transformations and agent actions.

Constitutional constraints

Model who may change which rules, memory regions, permissions and shared commitments.

Threat scenarios

Isolate evidence contamination, hallucination propagation, unauthorized rewrites and authority confusion.

Benchmark protocol

Define reference inputs, run logs, failure categories and comparable metrics across repeated experiments.

03 / RESEARCH

Critical validation questions

  1. What counts as a provenance-preserving transfer between two agents?
  2. Can a violation be detected before it enters shared memory?
  3. Which results can be replicated under identical baseline conditions?

Development pathway

Frozen baseline → scenario catalogue → controlled runs → integrity metrics → generalization
